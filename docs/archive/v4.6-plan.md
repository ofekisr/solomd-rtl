# SoloMD 4.6 — "UI Rebuild + Knowledge Graph Parity" Project Plan

> Status: direction locked; implementation agents not yet started.
> Decisions (user, 2026-06-10):
> - **Design direction**: learn from Tolaria's restrained, premium feel, but make it SoloMD's own — neutral grey surfaces + warm orange accent `#ff9f40`, 8px corner radius, restrained shadows, system UI font + monospace editor. **Do not copy its cool blue-grey; keep the brand's warm colour.**
> - **Cadence**: build everything in parallel at once and merge at the end (high-risk path; the user knows and accepts this).

---

## 0. One-line Goal

Ship **4.6**: **surpass Tolaria across the UI/UX layer** (replace hand-written ad-hoc CSS with a real design system + Vue component library), and close the **7 feature gaps** with Tolaria (property inspector, type-driven sidebar, typed relationships, relationship graph, saved filter views, Inbox workflow, tldraw whiteboard).

**Definition of Done:**
1. The whole app sits on one set of design tokens + one component library; no more 56 `<style scoped>` blocks each writing its own modal/dropdown/button.
2. All 7 features work, and each passes end-to-end self-tests through the `solomd-dev` MCP bridge + Rust unit tests (where Rust is involved) + CLI/MCP smoke tests.
3. All data is Markdown-first: new features read and write only YAML frontmatter / fenced blocks / the `.solomd/` sidecar; vaults stay cross-compatible with Tolaria.
4. Strings complete in all 14 languages; light/dark + 8 themes do not regress.
5. Opening a vault in both SoloMD and Tolaria breaks neither (cross-compatibility test).

## 1. Current-state Diagnosis — Why We "Look Raw"

From a survey of the front-end shell (full scan of `app/src`):

| Dimension | Current state | Problem |
|---|---|---|
| Design-system maturity | ~40% | 11 core colours (`--bg/--text/--accent`, …) + 8 themes, but **no spacing/radius/shadow/z-index scales** |
| Component library | Almost none | Buttons/dropdowns/modals/inputs are **inline markup + scoped CSS**, rewritten in every container |
| Duplication | Severe | `.dropdown__menu` copied 5 times; modal backdrop + radius + shadow + z-index copied 5+ times |
| Style islands | 56 | 56 components each with their own `<style scoped>`; shadows/borders/density inconsistent |
| Hard-coding | Many places | Magic values such as `rgba(255,159,64,0.08)` inlined instead of `--accent-soft` |

**Root cause**: there is no "token layer + headless component library" middle layer. Tolaria looks premium because of Tailwind 4 `@theme` token discipline + Radix/cva component primitives + consistent density / focus rings / micro-interactions. **That layer is what we add.**

✅ Reusable assets we keep: `Icons.vue` (centralised SVGs), `Toast.vue` + the toasts store, the `themes.ts` theme pipeline, the CodeMirror theme generator.

## 2. Design System (the 4.6 foundation / contract shared by everyone)

> This is the only trunk in the "fully parallel" plan: all 7 feature agents take colours and components **from this written contract** instead of inventing their own. Even in parallel, this spec is fixed first to avoid rework.

### 2.1 Token Layer — `app/src/styles/tokens.css` (new)

A single `:root` token source; light/dark + 8 themes override only the semantic layer. Scales (previously missing entirely):

```
/* spacing (8pt base) */   --sp-1:4px --sp-2:8px --sp-3:12px --sp-4:16px --sp-5:24px --sp-6:32px
/* radius */               --r-sm:4px --r-md:8px --r-lg:12px --r-full:999px   (8px baseline)
/* shadows (restrained) */ --sh-1: 0 1px 2px rgba(0,0,0,.06)
                           --sh-2: 0 4px 12px rgba(0,0,0,.08)
                           --sh-pop: 0 8px 28px rgba(0,0,0,.12)
/* border */               --bd:1px solid var(--border)
/* z layers */             --z-pane:10 --z-sticky:50 --z-pop:1000 --z-modal:2000 --z-toast:3000
/* motion */               --ease:cubic-bezier(.2,.7,.2,1) --dur-fast:120ms --dur:180ms
/* focus ring */           --ring: 0 0 0 2px var(--bg), 0 0 0 4px var(--accent)
```

Semantic colour layer (keeps existing variable names and fills the gaps; **accent locked to warm orange**):
```
--accent:#ff9f40  --accent-fg:#1a1a1a  --accent-soft:rgba(255,159,64,.10)  --accent-ring:rgba(255,159,64,.45)
--bg --bg-elev --bg-hover --bg-active --border --text --text-muted --text-faint --danger --success --warning
```
> Concrete light/dark values are in §2.4 (extracted from the Tolaria design survey, then aligned to SoloMD's warm palette).

### 2.4 Tolaria Design Tokens (aligned to SoloMD warm orange)

Measured Tolaria values (to align density, hierarchy and warm neutral greys); **every accent is swapped for SoloMD warm orange**:

| Role | Tolaria light | Tolaria dark | SoloMD 4.6 uses |
|---|---|---|---|
| App background | `#FFFFFF` | `#1F1E1B` | light `#FFFFFF` / dark `#1F1E1B` (warm black, not pure black) |
| Sidebar background | `#F7F6F3` | `#191814` | same (warm grey — key to the premium feel) |
| Panel/card | `#FFFFFF` | `#23221F` | same |
| Button background | `#EBEBEA` | `#34322D` | same |
| Border | `#E9E9E7` | `#34322D` | same |
| Body text | `#37352F` | `#E6E1D8` | same (warm dark grey, not `#000`) |
| Secondary text | `#787774` | `#B8B1A6` | same |
| Faint text | `#B4B4B4` | `#7F776D` | same |
| **Accent** | `#155DFF` (blue) | `#78A4FF` | **`#ff9f40` light / `#ffa54d` dark** (our orange replaces blue) |
| **Focus ring** | blue | blue | **orange `#ff9f40`** (3px — the key "premium" detail) |
| Semantic | green `#38A169` red `#E53E3E` | lifted versions | keep (not primary colours) |

Fonts: UI = `Inter, -apple-system, …`; monospace = `IBM Plex Mono`; **base 14px / line-height 1.5 / `font-synthesis:none` / antialiased**.
Radius: base **8px** (sm 2 / md 6 / lg 8 / xl 12). Shadows: graded xs/sm/md/lg. Transitions: **150–200ms**.

**The three ingredients of the "premium feel" (we follow them)**: ① token discipline (semantic names, no inline magic values) ② consistent density (36px buttons, 8px gaps, 24px card padding) ③ one 3px focus ring + 150ms micro-transitions + warm neutral greys (no harsh pure black/white). We only swap blue for orange and Radix/cva for Vue headless; the rest of the discipline is copied as is.

## 3. The Seven Feature Workstreams

> Common thread: **Markdown-first, almost no new Tauri commands** (reuse `workspace_index_*` + `write_file`/`read_file`). The heavy lifting is writing Vue against the §2 component library. Each feature = one isolated worktree agent.

| # | Feature | Data model (all Markdown-first) | Reuses | New Tauri | Days | Depends on |
|---|---|---|---|---|---|---|
| F1 | **Property inspector** ⌘⇧I | YAML frontmatter is the single source of truth; type inference at render time (extends `lib/bases.ts`); type overrides/pins stored in `.solomd/properties.json` | workspaceIndex.frontmatter, bases inference, wikilinks, BacklinksPanel navigation pattern, right-sidebar pane mechanism | `update_frontmatter_property` / `delete_frontmatter_property` (surgical serde_yaml rewrite that keeps body bytes unchanged) | 6.5 | design system + property engine |
| F2 | **Type-driven sidebar** | `type:<Name>` members + `type:Type` definition notes (title = type name; `_icon/_color/_order/_pinned_properties`); mirrors Tolaria for vault cross-compatibility | workspaceIndex (type already parsed), FileTree sidebar pattern, F1's property value formatting | none in MVP (member writes via `write_file` + js-yaml splice) | 5 | design system + property engine |
| F3 | **Typed relationships** | Any non-reserved frontmatter key containing a `[[wikilink]]` is a relationship; forward edges live in YAML, inverse edges are computed in memory across the vault | wikilinks/backlinks, workspaceIndex | `workspace_index_referenced_by` (server-side reverse lookup on the in-memory index) | 5 | workspaceIndex (exists) |
| F4 | **Relationship graph (Neighborhood)** | No new conventions; a relationship is a key whose value is a wikilink; out-edges = those keys, in-edges = reverse scan | workspace_index_files/backlinks/resolve | none (v1 client-side; optional `workspace_index_neighborhood` for large vaults in the next minor) | 3.5 | workspaceIndex |

| F7 | **tldraw whiteboard** | Keep Tolaria's on-disk format: a fenced ` ```tldraw id=.. height=.. ` block whose body is `TLStoreSnapshot` JSON; cross-compatible | file read/write, git history, backlinks | none (snapshot inline; optional `whiteboard_export_png` in the next minor) | 6 | design system |

**Total ~35.5 person-days** (wall-clock in parallel is set by the slowest chain = F1, 6.5 days).

### Key Technical Notes
- **F1 YAML round-trip fidelity** is the biggest risk: serde_yaml 0.9 drops comments and may reorder keys or re-quote → noisy git diffs. **Mitigation**: surgical block edits (change only the target key, keep order in place, body verbatim) + table-driven fixtures in `frontmatter_edit_test.rs` (CJK keys, inline arrays, quotes, block-scalar bodies, synthesising missing frontmatter, a leading H1).
- **F5 touches `bases.ts`**: `applyFilters` moves from flat AND to a recursive `FilterGroup` and must stay compatible with existing flat callers → this is part of the "property engine" foundation, and F1/F2 benefit too.
- **F7 tldraw is a heavy dependency** (~1–2 MB) and fragile under Tauri/zoom: it needs a zoom-aware viewport patch, text-measurement guards, guards for denied platform permissions, and dialog re-hosting — its own worktree, merged last, size isolated behind a dynamic import.

## 4. Agent Assignment & Parallel Orchestration

**Dependency graph:**
```
        ┌──────────────────────────────────────────────────────────┐
   [foundation] design system (tokens + ui/ library) + property engine (bases.ts generalisation)
        └───────────────┬──────────────────────────────────────────┘
                        ↓ everyone takes from the written contract §2 + §F5
   F1 properties  F2 type sidebar  F3 relationships  F4 graph  F5 views  F6 Inbox  F7 whiteboard
        └─────────────── unified merge + integration self-test ──────────┘
```

**Orchestration (worktree isolation, matching "fully parallel, merge at the end"):**
1. **Phase 0 (foundation, ~1 day, trunk)**: 1–2 agents land `tokens.css` + the 12 `ui/` components + the `bases.ts` generalisation, and migrate the shell/SettingsPanel/CommandPalette/Dialogs onto them. **Merge into the `feat/v4.6` trunk first**, because it is a single shared file contract that all 7 features import — the one serial point in "fully parallel" that cannot physically be avoided (otherwise 7 agents invent 7 colour sets = guaranteed rework).
2. **Phase 1 (7 features, fully parallel)**: 7 agents, each with `isolation: worktree`, branched from `feat/v4.6`, never touching each other's files (almost zero file overlap between features — see §3 new_files). Each agent brings its own self-tests.
3. **Merge phase**: merge back in the order F6→F4→F3→F2→F1→F5→F7 (light→heavy, fewest→most dependencies), running integration self-tests after each merge. Conflicts concentrate in `App.vue` (right-sidebar pane registration), `settings.ts` (toggles), `CommandPalette.vue` and `i18n/en.ts` — these use **additive registration** (each feature adds its own lines) to keep conflicts minimal.

> Note: the user chose "fully parallel". The **feature layer** is fully parallel (7 running at once); only the design-system contract is fixed first as trunk. That is the correct engineering reading, not a retreat to "UI first, then wait for confirmation".

## 5. Self-test Strategy (mandatory for every feature)

Before declaring done, every feature agent **must**:
1. **Disk round-trip**: create a fixture with `solomd_write_file` → drive the feature → assert with `solomd_read_file` that the body is byte-correct and only the target changed.
2. **UI path**: drive the real UI with `solomd_dev_click`/`_text`/`_eval` (needs `pnpm tauri dev`) + verify visually with `solomd_screenshot`.
3. **Rust unit tests** (where Rust is involved): `cargo test` (F1 frontmatter round-trip, F3 reverse lookup).
4. **Git safety**: compare `solomd_git_status` before and after to confirm one edit = one clean, minimal diff.
5. **CLI + MCP smoke**: per global rule #4, expose new capabilities in mcp-server + a CLI example (reads first; writes gated).
6. **i18n**: new strings go into `en.ts`, with placeholders in all 14 languages.

> Compliance red line: **no declaring done until self-tests pass** (global CLAUDE.md #2). Where synthetic keyboard events cannot drive tldraw, fall back to store-level checks + screenshot verification (see memory `reference_dev_bridge_synthetic_events`).

## 7. Risks & Rollback

- **Merge conflicts from full parallelism**: additive registration + worktrees; "registration zone" comment anchors in `App.vue`/`settings.ts` reduce conflicts.
- **Design regressions**: M0 first captures screenshot baselines of the sample page + main UI; compare before/after as each component is replaced.
- **Noisy YAML diffs (F1)**: surgical edits + round-trip fixtures as the gate; no merge until they pass.
- **tldraw size/fragility (F7)**: dynamic import; on failure degrade gracefully to a read-only JSON preview; merged separately and last, so it can be rolled back alone without affecting the other 6.
- **Scope creep**: since SoloMD has no native Type system, F1 drops Tolaria's Type/Workspace picker; each feature's "optional next minor" items (MCP/CLI verbs, neighborhood/png-export Rust commands) are deferred per memory `feedback_cli_mcp_cadence`, not squeezed into this release.
