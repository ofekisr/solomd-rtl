# SoloMD 4.6.1 — “Refining the Knowledge Graph Layer” (Releasing tomorrow)

> In version 4.6, we implemented seven features to match Tolaria—all developed rapidly in parallel as **MVPs (Minimum Viable Products)**. Version 4.6.1 introduces no new features; instead, it focuses on three specific goals: achieving **production-grade depth**, ensuring **consistency with our design system**, and delivering a **polished, refined experience**.
> Regarding the competition: Tolaria’s latest release (version 2026.6.10, launching today) is limited to localization, a “Copy Git URL” function, and menu fixes—with **no new structural features**. We have reached parity across the board and hold a significant lead; we have also made a deliberate decision *not* to replicate their unique paradigm (the BlockNote block-based editor).

## Acceptance Criteria
- 7 new features transitioned from MVP to **production-grade** (covering edge cases, performance, and UX nuances)—no rough edges.
- All new panels utilize the design system components located in `app/src/ui/` (replacing the ad-hoc CSS used in F2/F4/F5), ensuring visual consistency and a "polished" feel.
- All checks—`vue-tsc`, `vite build`, and `cargo test`—must pass; all real-time dev-bridge QA tests cleared; no regressions in the main entry bundle.
- Release **v4.6.1** tomorrow (includes signed macOS DMG, 4× APKs, AAB, and CI builds for Windows/Linux; update the official website only after the release is finalized).

## Three Workstreams

### ② Reinforcing and Amplifying Differentiation (Building a Moat)
- **Design System Consistency Audit**: Ensure uniform density, corner radii, focus rings, and shadows across the entire app (not just the new panels)—this is the key to moving beyond a "raw" feel and achieving a level of refinement that surpasses Tolaria.
- Ensure new features integrate with our proprietary layers (e.g., Relationships/Types) so they are accessible to the Agent panel and MCP tools (e.g., via `get_relationships` or `list_types`, provided the implementation cost is low).
- Verify responsive adaptation for the new panels on mobile (iPad).

### ③ Copy Note Git URL (Similar to the feature in Tolaria 2026.6.10; low-effort, high-value)
- Add a "Copy Git URL" option to the Command Palette and the note right-click menu. This will retrieve the workspace's `git remote` and the current note's relative path, construct the URL (e.g., `<remote>/blob/<branch>/<path>`), and copy it to the clipboard.

## Orchestration and Quality Discipline (Lessons learned from v4.6)
- Branching: Create `feat/v4.6.1` from `main`. Agents must perform a `git merge feat/v4.6.1` before starting work (to avoid the issues encountered last time when branching from an outdated baseline).
- Validation: Each agent must pass a dual-check process: `vue-tsc --noEmit` **plus** `vite build` (since `vue-tsc` may fail to catch errors in SFC templates).
- Post-merge: I will conduct a unified integration QA (using the `dev-bridge` test suite and screenshots) before release; we will not rely on agents to self-report completion.
- Handling Conflicts: For high-conflict areas (e.g., `App.vue`, settings, i18n, Rust handlers), we will use an additive registration approach, and I will manually resolve any conflicts.
